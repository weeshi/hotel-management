01

🏗️ العمارة التقنية المُحسّنة

هندسة متعددة الطبقات تفصل بين الـ UI ومنطق الأعمال والبيانات، مع طبقات Repository و Queue و Gateway.

المخطط العام

🌐 HTTP / HTTPS
🔒 طبقة النقل الآمنجميع الاتصالات بين المتصفح والخادم مشفرة عبر HTTPS مع HSTS. يمنع هجمات man-in-the-middle واعتراض البيانات.
Next.js (App Router)
API Routes ← بديل Express
⚡ خادم واحد يجمع Frontend + Backendيحتوي Next.js على نظام API Routes المدمج الذي يلغي الحاجة إلى خادم Express منفصل. هذا يقلل التعقيد، يلغي CORS، ويسرّع النشر. يمكنك كتابة API endpoints في نفس المشروع.
Middleware Layer
Auth | CSRF | RateLimiter | Validate | Audit
🛡️ طبقة الحماية والتحقققبل الوصول إلى الخدمات، يمر الطلب عبر سلسلة من الـ Middleware: التحقق من صحة التوكن (Auth)، منع هجمات CSRF، تحديد عدد الطلبات (Rate Limiter)، التحقق من صحة البيانات (Zod Validation)، وتسجيل العملية (Audit Log).
Service Layer (Business Logic)
🧠 قلب النظام — منطق الأعمالهنا يتم تنفيذ كل القواعد التجارية: إنشاء الحجوزات، حساب الفواتير، إدارة الخدمات، تطبيق الخصومات والضرائب. كل Service مستقل تماماً ويستدعي الـ Repository Layer للوصول إلى البيانات.
Repository Layer (Data Access)
Abstracted from Prisma
🗃️ واجهة الوصول إلى البياناتطبقة تفصل منطق الأعمال عن قاعدة البيانات. كل كيان (Booking, User, Room) له Repository خاص به. هذا يسمح باختبار الـ Services بشكل منفصل، وتغيير ORM أو قاعدة البيانات مستقبلاً دون تعديل كود الخدمات.
External Services Layer
Stripe | PayPal | MobiCash | Email
🔌 خدمات خارجية — قابلة للتبديلطبقة تجريدية تسمح باستبدال أي مزود خدمة دون تغيير كود النظام. حالياً: بوابات الدفع (Stripe، PayPal، موبي كاش)، البريد الإلكتروني (Resend)، والرسائل النصية. يمكن إضافة مزود جديد بكتابة Gateway واحد فقط.
🗄️ PostgreSQL  |  ⚡ Redis (Cache/Queue)  |  🔔 Stripe Webhooks
📦 البنية التحتية للبياناتPostgreSQL هي قاعدة البيانات الرئيسية لكل البيانات الهيكلية. Redis يُستخدم للتخزين المؤقت (Cache) وسير الانتظار (Queue) للمهام غير المتزامنة كالإيميلات والإشعارات. Webhooks من Stripe تخطر النظام بأحداث الدفع في الوقت الفعلي.

طبقات المشروع

الطبقةالمسارالوظيفة

نمط الـ Repository Layer

repositories/
  • base.repository.ts — CRUD generic
    ⭐ CRUD عام يوفر دوال أساسية (findById, create, update, delete, paginate) لجميع الـ Repositories. يقلل تكرار الكود بنسبة 70% ويوحد واجهة الوصول للبيانات.
  • booking.repository.ts
    📅 إدارة الحجوزات استعلامات معقدة للتوفر (availability check)، البحث بالتواريخ، الفلترة حسب الحالة (مؤكد/ملغي/منتهي)، تقارير الإشغال، والتكامل مع RatePlan لاحتساب السعر.
  • room.repository.ts
    🚪 إدارة الغرف البحث برقم الغرفة، الفلترة حسب الحالة (متاح/مشغول/صيانة)، التوفر في تاريخ معين، والحصول على الغرف المتاحة لنوع معين في فترة زمنية.
  • folio.repository.ts
    💰 إدارة الفوترة إنشاء Folio، إضافة معاملات (FolioTransaction) مع حساب الضريبة التلقائي، حساب الرصيد (balance)، استعلامات التقارير المالية، وترحيل الشحنات المجدولة.
  • guest.repository.ts
    👤 إدارة الضيوف البحث بالإيميل أو رقم الهاتف، سجل الحجوزات السابقة، نقاط الولاء، وإدارة العناوين والبيانات الشخصية للضيوف المسجلين.
  • service.repository.ts
    🛎️ إدارة الخدمات الفلترة حسب فئة الخدمة (مطعم، تنظيف، نقل)، البحث بالاسم، جلب الخدمات النشطة فقط، وحساب السعر مع الضريبة حسب TaxRule.
  • rate-plan.repository.ts
    🏷️ خطط الأسعار البحث عن أرخص خطة سعرية لتاريخ معين، تطبيق minStay، التحقق من صحة الفترة (startDate/endDate)، وربط خطة السعر بسياسة الإلغاء المناسبة.
services/
  • booking.service.ts ← BookingRepository
    📋 منطق الحجوزات التحقق من توفر الغرفة، حساب السعر الإجمالي (بما في ذلك الموسمية)، تطبيق سياسة الإلغاء، إدارة حالات الحجز (Pending → Confirmed → CheckedIn → CheckedOut → Cancelled).
  • folio.service.ts ← FolioRepository
    🧾 قلب نظام الفوترة إنشاء Folio عند Check-in، ترحيل RoomCharge تلقائياً كل ليلة، إضافة BookingService إلى الفاتورة، حساب الضريبة المركبة، تطبيق الخصومات، وتسوية الفاتورة عند Check-out.
  • payment.service.ts ← Gateway Abstraction
    💳 طبقة دفع مجردة توحيد واجهات جميع بوابات الدفع (Stripe, PayPal, موبي كاش, إدفع لي) خلف واجهة واحدة. تتعامل مع الإنشاء والتأكيد والاسترداد وإشعارات Webhooks دون أن تعرف الخدمة أي بوابة تستخدم.
  • pricing.service.ts ← RatePlan + موسمية
    💲 التسعير الذكي تحديد السعر المناسب تلقائياً حسب: الموسم (High/Low)، مدة الإقامة (تطبيق minStay)، يوم الأسبوع (عطلة/عمل)، خطة السعر المطبقة، وسياسة الإلغاء المرتبطة.
  • cancellation.service.ts ← سياسات الإلغاء
    ❌ الإلغاء والاسترداد حساب مبلغ الاسترداد بناءً على قواعد سياسة الإلغاء (JSON rules)، إنشاء Refund تلقائي عبر بوابة الدفع، تحديث حالة الحجز والفوليو، وإشعار العميل.
  • notification.service.ts ← Queue-based
    📨 الإشعارات غير المتزامنة إرسال إيميلات و SMS عبر Bull Queue (Redis) مع إعادة محاولة تلقائية عند الفشل. يدعم: تأكيد الحجز، تذكير 24 ساعة قبل الدخول، فاتورة الخروج، وإشعار الإلغاء.
  • audit.service.ts ← AuditLog
    📝 التدقيق التلقائي تسجيل كل عملية حساسة في النظام: من فعلها، متى، من أي IP، القيمة القديمة والجديدة. أمثلة: تعديل سعر غرفة، استرداد مبلغ، إلغاء حجز، إضافة موظف جديد.
gateways/
  • payment-gateway.interface.ts
    🔌 واجهة بوابة الدفع الموحدة Strategy Pattern — تعرّف الواجهة الأساسية (interface) التي يجب على كل بوابة دفع تنفيذها: createPaymentIntent, authorize, capture, refund, verifyWebhook. أي بوابة جديدة تكتب class واحد implement هذه الواجهة.
  • stripe.gateway.ts
    💳 Stripe البوابة العالمية الأكثر انتشاراً. تدعم: بطاقات ائتمان مع 3D Secure، Apple Pay، Google Pay، Pre-authorization (تجميد مبلغ تأمين)، Partial Refund، Webhooks (payment_intent.succeeded/failed).
  • paypal.gateway.ts
    💳 PayPal محفظة رقمية عالمية. تدعم: PayPal Wallet، Credit Card عبر PayPal، Partial Refund، Webhooks (PAYMENT.CAPTURE.COMPLETED/REFUNDED). مثالية للحجوزات الدولية.
  • mobicash.gateway.ts
    📱 موبي كاش (Libyana) محفظة إلكترونية ليبية من شركة ليبيانا. تدعم: دفع عبر رمز QR، تحويل فوري بين المحافظ، سحب نقدي من الوكلاء. مناسبة للدفع المحلي في ليبيا.
  • idfa3ly.gateway.ts
    💼 إدفع لي (Idfa3ly) منصة دفع إلكتروني ليبية. تدعم: بطاقات مدى المحلية، الدفع عبر التطبيق، API مفتوح للتكامل المباشر مع المواقع والتطبيقات.
  • yaserpay.gateway.ts
    💳 يسر باي (YaserPay) محفظة رقمية ليبية. تدعم: تحويل بين المستخدمين، سحب وإيداع نقدي عبر الوكلاء، QR Code للدفع في المتاجر والفنادق.
  • onepay.gateway.ts
    💳 ون باي (OnePay) منصة دفع إلكتروني ليبي. تدعم: بطاقات ائتمان مسبقة الدفع، دفع الفواتير، API Gateway للتكامل مع أنظمة الفوترة.
  • email.gateway.ts
    ✉️ البريد الإلكتروني إرسال الإيميلات عبر Resend/SendGrid. يدعم: قوالب HTML (تأكيد حجز، فاتورة، تذكير)، مرفقات PDF، وتتبع حالة الإرسال (تم/فشل).
  • sms.gateway.ts
    📱 الرسائل النصية إرسال SMS للعملاء عبر مزود محلي (اختياري). يُستخدم لإشعارات الحجز العاجلة وتذكيرات المواعيد. يمكن تعطيله إذا لم يكن مطلوباً.

03

🗄️ نموذج قاعدة البيانات الكامل

25+ نموذج Prisma مع علاقات متكاملة، فهارس أداء، ودعم كامل لنظام الفوترة الفندقي.

النماذج الأساسية

  • Hotel — معلومات الفندق، الإعدادات، أوقات الدخول/الخروج
  • User — موظفون بأدوار (Admin, Reception, Manager) + 2FA
  • RefreshToken — 🔴 NEW تدوير الـ Refresh Token مع عائلة
  • Guest — الضيوف، التحقق من الإيميل، نقاط الولاء
  • RoomType — أنواع الغرف، المرافق، الصور
  • Room — الغرف الفردية + حالة التنظيف 🔴 NEW
  • RatePlan — 🔴 NEW أسعار موسمية مع minStay وسياسة إلغاء
  • CancellationPolicy — 🔴 NEW قواعد إلغاء مرنة (JSON rules)

الحجوزات والفوترة

  • Booking — رقم تسلسلي، حالة، مصدر، سياسة إلغاء
  • BookingRoom — 🔴 NEW حجوزات متعددة الغرف
  • ServiceCategory — فئات الخدمات (قابلة للتوسع)
  • Service — خدمات فردية مع ربط ضريبي
  • BookingService — خدمات مرتبطة بالحجز (أثناء الحجز أو أثناء الإقامة)
  • Folio — حساب الغرفة الشامل
  • FolioTransaction — كل حركة مالية + ضريبة لكل معاملة
  • ScheduledCharge — 🔴 NEW شحنات مجدولة (إيجار ليلي تلقائي)
  • RoomCharge — 🔴 NEW شحن الإيجار الليلي لكل غرفة
  • FolioDiscount — 🔴 NEW خصومات (نسبة أو مبلغ)

المدفوعات والتدقيق

  • Payment — دعم Pre-auth, Idempotency, Metadata
  • Refund — 🔴 NEW استرداد كامل وجزئي
  • Invoice — فواتير مع تفصيل ضريبي
  • TaxRule — 🔴 NEW ضرائب متعددة (VAT, سياحية, بلدية)
  • AuditLog — 🔴 NEW سجل تدقيق كامل
  • Notification — 🔴 NEW إشعارات (Email, SMS, WhatsApp)
  • HousekeepingTask — 🔴 NEW مهام التدبير المنزلي

الشراكات الخارجية

  • ApiPartner — API Key + Secret + IP Whitelist + حد يومي
  • WebhookEndpoint — مع إعادة محاولة (Retry + Interval)
فهارس أداء
  • (hotelId, status, checkIn, checkOut)
  • (roomId, date) على RoomCharge
  • (hotelId, entity, entityId) على AuditLog
  • (hotelId, status) على Notification

⭐ الميزات الجديدة المضافة

الميزات التي أضفناها بعد تحليل الفجوات — مرتبة حسب الأولوية.

الأسعار الموسمية (Rate Plans)

خطط أسعار ديناميكية تغطي فترات متعددة مثل الصيف، رمضان، العيد، وعطلات نهاية الأسبوع. تدعم minStay (الحد الأدنى لليالي)، سياسات إلغاء مختلفة لكل خطة، وتطبيق السعر التلقائي حسب تاريخ الحجز. مثال: خطة "الصيف 2026" = 450 د.ل/ليلة مع إلغاء مجاني 48 ساعة، خطة "رمضان" = 350 د.ل/ليلة بدون استرداد.

MVP

سياسات الإلغاء

نظام قواعد JSON مرن يدعم 3 مستويات أساسية: مرنة (إلغاء مجاني قبل 48 ساعة من الدخول)، معتدلة (استرداد 50% قبل 24 ساعة)، صارمة (لا استرداد بعد تأكيد الحجز). تُربط كل خطة سعرية بسياسة إلغاء منفصلة، مما يسمح بمرونة تسعيرية كاملة. مثال: ضيف ألغى قبل يومين ← استرداد كامل تلقائي.

MVP

الإلغاء مع استرداد

سير عمل كامل وآلي: ضيف يلغي ← النظام يحسب مبلغ الاسترداد حسب سياسة الإلغاء ← ينشئ Refund في بوابة الدفع (كلي أو جزئي) ← يحدّث Folio ← يرسل إشعاراً للعميل بالإيميل. يدعم: الإلغاء قبل الدخول، الإلغاء أثناء الإقامة (مع احتساب الليالي المستخدمة)، و No-show.

MVP

حجوزات متعددة الغرف

عبر نموذج BookingRoom الوسيط، يمكن للضيف حجز غرفتين أو أكثر في حجز واحد مع فاتورة موحدة. مثال: عائلة من 5 أفراد تحجز غرفتين متجاورتين (غرفة رقم 201 بسعر 450 د.ل/ليلة + غرفة رقم 202 بسعر 350 د.ل/ليلة) ← فاتورة واحدة عند الخروج.

MVP

الإشعارات (Queue-based)

نظام إشعارات غير متزامن عبر Bull + Redis. يُرسل إيميلات تأكيد الحجز فوراً، تذكير قبل 24 ساعة من الدخول ("غداً موعد وصولك في فندقنا")، فاتورة الخروج PDF، وإشعار الإلغاء. مع إعادة محاولة تلقائية (3 محاولات) إذا فشل الإرسال.

مرحلة 2

التدبير المنزلي

إدارة تنظيف الغرف بجدولة ذكية: عند تسجيل الخروج ← حالة الغرفة ← DIRTY ← تعيين لعامل النظافة ← IN_PROGRESS ← تفتيش ← INSPECTED ← متاحة للحجز. يدعم أولويات (عاجل/عادي) وتعيين موظفين محددين لكل مهمة.

مرحلة 2

التقارير الأساسية

لوحة تحليلية مع المقاييس الفندقية الأساسية: Occupancy Rate = (ليالٍ مشغولة ÷ إجمالي الليالي) × 100، ADR (Average Daily Rate) = إيراد الغرف ÷ ليالٍ مشغولة، RevPAR (Revenue Per Available Room) = إيراد الغرف ÷ إجمالي الغرف المتاحة. مع تصفية حسب اليوم/الأسبوع/الشهر.

مرحلة 2

سجل التدقيق (Audit Log)

تتبع كل عملية حساسة في النظام مع 6 أبعاد: من (user)، متى (timestamp)، إيش (action)، على إيش (entity + entityId)، من وين (IP + userAgent)، التغيير (oldValue → newValue). أمثلة: "Admin@2026-06-15 14:30 ← غيّر سعر الغرفة 201 من 450 إلى 550"، "Reception@2026-06-15 15:00 ← سجّل دخول الضيف أحمد".

مرحلة 2

2FA — توثيق ثنائي

تفعيل التوثيق الثنائي (TOTP) عبر Google Authenticator للمستخدمين. خطوات التفعيل: الإعدادات ← تفعيل 2FA ← مسح QR code ← إدخال رمز التحقق للتأكيد. يدعم رموز احتياطية (backup codes) لاستعادة الوصول في حال فقدان الجهاز.

مرحلة 3

الخصومات

نوعان من الخصومات: نسبة مئوية (مثل خصم 10% للعملاء الدائمين) ومبلغ ثابت (مثل 50 د.ل خصم تعويضي). صلاحية كل دور: Admin بدون حد، Manager حتى 15% من إجمالي الفاتورة. يُسجل الخصم في FolioDiscount مع توقيع المسؤول المخوّل.

مرحلة 3

فواتير PDF

توليد فاتورة PDF قابلة للطباعة تحتوي على: شعار الفندق وعنوانه، رقم الفاتورة التسلسلي، بيانات الضيف، تفصيل البنود (إيجار ليلي + خدمات + ضرائب)، رمز QR للدفع الإلكتروني، وتوقيع موظف الاستقبال. تُرسل تلقائياً بالإيميل عند تسجيل الخروج.

مرحلة 3

Partner API

واجهة API موثقة (OpenAPI 3.0) للربط مع منصات الحجز العالمية مثل Booking.com و Expedia. تدعم: API Key + HMAC Signature للتحقق من الهوية، IP Whitelist للتقييد الجغرافي، Rate Limit مخصص لكل شريك، و Webhooks (booking.created, booking.cancelled, payment.completed).

مرحلة 3

نظام الصيانة (Maintenance Tracking) 🔴 جديد

تسجيل أعطال الغرف (مكيف لا يعمل، سباكة، كهرباء) مع تحديد الأولوية (عاجل/عادي/منخفض)، تعيين لفني الصيانة، تتبع حالة الإصلاح، وجدولة الصيانة الدورية (مثل فحص المكيفات كل 3 أشهر). يُنشئ تذكيرات تلقائية عند تأخير الإصلاح.

مرحلة 3

تطبيق ويب للهاتف (PWA) 🔴 جديد

تحويل موقع الحجز إلى تطبيق ويب تقدمي (Progressive Web App) يمكن تثبيته على شاشة الهاتف الرئيسية مثل التطبيقات العادية. يدعم الإشعارات اللحظية (push notifications) لتأكيد الحجز والتذكير، ويعمل دون اتصال جزئي (offline mode) لعرض الحجوزات السابقة.

مرحلة 3

تكامل التقويم (Calendar Sync) 🔴 جديد

مزامنة توفر الغرف مع Google Calendar و iCal تلقائياً. يُنشئ كل حجز حدثاً في التقويم باسم الغرفة وتاريخ الدخول/الخروج. إذا غيّر الضيف حجزه ← يُحدّث الحدث تلقائياً. يساعد موظفي الاستقبال على رؤية التوفر في لمحة دون فتح النظام.

🌐 الموقع الإلكتروني العام — SaaS فقط

الواجهة العامة لتطبيق حجوزات الفنادق على السحابة. متاحة فقط لمستخدمي SaaS، غير متوفرة في On-Premise.

هيكل الصفحات

صفحات عامة (public)

  • الصفحة الرئيسية — بحث عن فنادق، تصفح، فلترة (مدينة/نجوم/السعر)، خريطة، عروض مميزة
  • صفحة الفندق — صور + فيديو، وصف، قائمة الغرف وأنواعها، التقويم الشهري للتوفر، التقييمات، سياسة الإلغاء
  • صفحة الحجز — اختيار تواريخ الدخول/الخروج، أنواع الغرف، عدد الضيوف، وجبات إضافية، مراجعة السعر
  • تسجيل الدخول — إنشاء حساب (نزيل/فندق/مسوق)، توثيق البريد، استعادة كلمة المرور

لوحة التحكم (dashboard)

  • الفنادق — إضافة/تعديل/حذف فنادق، إدارة الصور والفيديو، تحديد أنواع الغرف والأسعار
  • الغرف — إدارة مخزون الغرف، تحديد التوفر، Rate Plans
  • الحجوزات — عرض/تأكيد/إلغاء حجوزات، تسجيل دخول/خروج النزلاء
  • Housekeeping — جدول تنظيف الغرف، تحديث حالة الغرفة (نظيفة/قيد التنظيف/صيانة)
  • الفواتير (Folio) — عرض فواتير النزلاء، إضافة رسوم إضافية، إصدار المبالغ المستردة
  • التقييمات — عرض تقييمات النزلاء والرد عليها
  • التقارير — إحصائيات الإشغال والإيرادات مع رسوم بيانية
  • الإعدادات — الملف الشخصي، الدفع، سياسة الإلغاء، Rate Plans

لوحة النزيل (guest)

  • حجوزاتي — عرض الحجوزات السابقة والقادمة، إلغاء، تعديل
  • فاتورتي (Folio) — عرض الفاتورة الحالية والمدفوعات والرسوم الإضافية
  • طلبات الخدمة — طلب تنظيف الغرفة، خدمة الغرف، الصيانة
  • تقييماتي — تقييم الإقامة بعد المغادرة

تدفق الحجز الكامل (متوافق مع نظام Folio والدفع)

تصفح الفنادق اختيار فندق اختيار تواريخ اختيار غرفة تسجيل/دخول مراجعة السعر تطبيق كود خصم اختيار الدفع تأكيد الدفع إنشاء Folio

🚀 النشر و CI/CD

استراتيجية نشر متكاملة مع Docker، نسخ احتياطي تلقائي، ومراقبة الأداء.

Docker Compose

services: postgres: image: postgres:16-alpine volumes: [pgdata:/var/lib/postgresql/data] healthcheck: test: ["CMD-SHELL", "pg_isready -U hotel"] redis: image: redis:7-alpine command: redis-server --requirepass ${REDIS_PASSWORD} app: build: . ports: ["3000:3000"] depends_on: postgres: { condition: service_healthy } redis: { condition: service_started } env_file: .env pgadmin: image: dpage/pgadmin4 profiles: [dev]

GitHub Actions CI/CD

# .github/workflows/ci.yml name: CI on: [push, pull_request] jobs: lint-and-typecheck: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: npm ci - run: npm run lint - run: npm run typecheck test: runs-on: ubuntu-latest services: postgres: { image: postgres:16-alpine } redis: { image: redis:7-alpine } steps: - uses: actions/checkout@v4 - run: npx prisma migrate deploy - run: npm test deploy: needs: [lint-and-typecheck, test] if: github.ref == 'refs/heads/main' steps: - run: docker build -t hotel-app . - run: docker push ${{ secrets.REGISTRY }}/hotel-app:latest

🗺️ خريطة التنفيذ — MVP إلى الإطلاق

خطة تنفيذ على 3 مراحل، من MVP الأساسي إلى الإطلاق الكامل مع جميع الميزات.

المرحلة 1 MVP Core — 12 أسبوع (أساسي للتشغيل)

الأسبوع 1-2: Foundation + تصميم DB Schema
التسليمات: قالب المشروع + Prisma Schema الكامل + CI
  • إنشاء Next.js + Turborepo + Tailwind + shadcn/ui + RTL
  • إعداد Docker (PostgreSQL 16 + Redis 7)
  • إنشاء Core Prisma Schema — Hotel, User, RoomType, Room, Booking, BookingRoom, Folio, FolioTransaction, ScheduledCharge, RoomCharge, Payment, Refund مع العلاقات والمؤشرات
  • GitHub Actions CI (lint, typecheck, test على كل PR)
  • نشر البيئة الأولى (رابط تجريبي)
الأسبوع 3-4: المصادقة والأمان
التسليمات: JWT + RBAC + تسجيل دخول
  • نظام JWT (Access 15min + Refresh 7days مع Rotation)
  • الأدوار (Admin, Manager, Reception) مع RBAC + CSRF + Rate Limiting
  • صفحة تسجيل الدخول بالعربية RTL
  • إدارة المستخدمين (إضافة/تعديل/تعطيل موظفين)
الأسبوع 5-7: الغرف والحجوزات
التسليمات: CRUD غرف + حجز أساسي + تقويم
  • CRUD أنواع الغرف + الغرف الفردية + المرافق والصور
  • نظام الحجوزات الأساسي (غرفة واحدة لكل حجز)
  • تقويم شهري ملون (متاح/مشغول/صيانة/قيد التنظيف)
  • سير عمل Check-in / Check-out مع تحديث حالة الغرفة
الأسبوع 8-10: Folio + فواتير
التسليمات: نظام فوترة + إيصال PDF
  • نظام Folio + FolioTransaction + ScheduledCharge (إيجار ليلي)
  • إضافة الخدمات للحجز (أثناء الحجز أو أثناء الإقامة)
  • دمج دفع Stripe الأساسي (بطاقة ائتمان)
  • تسوية الفاتورة عند الخروج + طباعة إيصال PDF
الأسبوع 11-12: اختبارات MVP + Fixes
التسليمات: MVP مستقر للتجربة الداخلية
  • اختبارات API (Supertest) لكل endpoints
  • اختبارات وحدة للخدمات (BookingService, FolioService)
  • إصلاح bugs + تحسين الأداء + فهرسة قاعدة البيانات
  • تغطية 80%+ من السيناريوهات الحرجة
✅ نهاية MVP — نظام مستقر جاهز للتشغيل التجريبي الداخلي

المرحلة 2 Beta — 8 أسابيع (ميزات متقدمة)

الأسبوع 13-14: Rate Plans + سياسات الإلغاء
التسليمات: إضافة جداول RatePlan + CancellationPolicy
  • Prisma: إضافة RatePlan, CancellationPolicy, SeasonalPricing
  • الأسعار الموسمية مع minStay وربط بسياسة الإلغاء
  • 3 مستويات للإلغاء (مرنة/معتدلة/صارمة)
  • حجوزات متعددة الغرف (BookingRoom) — غرفتين فأكثر
الأسبوع 15-16: Housekeeping + الصيانة
التسليمات: إضافة جداول HousekeepingTask + MaintenanceTicket
  • Prisma: إضافة HousekeepingTask, HousekeepingAssignment, MaintenanceTicket
  • جدولة تنظيف الغرف + تعيين موظفين + حالات الغرفة
  • نظام تذاكر الصيانة مع أولوية وصور
  • لوحة Housekeeping (عرض المهام + تحديث الحالة)
الأسبوع 17-18: إشعارات + تقارير
التسليمات: إضافة Notification + AuditLog
  • Prisma: إضافة Notification, AuditLog
  • نظام الإشعارات (Bull + Redis) — إيميلات تأكيد + تذكير + فاتورة
  • التقارير الأساسية (Occupancy Rate, ADR, RevPAR, Revenue)
  • سجل التدقيق — تتبع كل عملية حساسة
الأسبوع 19-20: QA + إطلاق Beta
التسليمات: إطلاق Beta لمستخدمين حقيقيين
  • اختبارات تكامل شاملة + تحمّل (Load Test)
  • إصلاح bugs + تحسينات UX
  • نشر Beta على نطاق فرعي (beta.example.com)
  • دعوة مستخدمين حقيقيين + جمع تغذية راجعة
✅ إطلاق Beta — مستخدمين حقيقيين + تغذية راجعة

المرحلة 3 الإطلاق الكامل — 8 أسابيع (Production)

الأسبوع 21-22: Partner API + Loyalty
إضافة جداول ApiPartner + Loyalty
  • Prisma: إضافة ApiPartner, PartnerMapping, LoyaltyPoints, LoyaltyTier
  • Channel Manager API (Booking.com، Expedia)
  • برنامج الولاء (نقاط لكل حجز، خصومات للعملاء المتكررين)
الأسبوع 23-24: أمان متقدم + بوابات
  • 2FA (Google Authenticator TOTP) للمستخدمين
  • PayPal Gateway + بوابات ليبية (موبي كاش، إدفع لي، يسر باي، ون باي)
  • الخصومات (نسبة / مبلغ ثابت) + فواتير PDF
  • 3D Secure + Pre-authorization
الأسبوع 25-26: Multi-Property + نطاق عام
  • دعم عدة فنادق (Multi-Property) للسلسلة الفندقية
  • الموقع العام مع نطاق مخصص + SSL
  • تحسين SEO + Open Graph + خرائط
  • تكامل Google Calendar / iCal Sync
الأسبوع 27-28: اختبارات شاملة + Staging + Go Live
  • اختبارات أمان (Penetration Test)
  • اختبار تحمّل (1000+ حجز متزامن)
  • Staging Environment + UAT مع فريق الفندق
  • تدريب فريق الاستخدام + توثيق المستخدم
  • 🚀 Go Live — الإطلاق الرسمي
